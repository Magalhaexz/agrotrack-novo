# SPRINT18W_BATCH_INDIVIDUAL_WEIGHING_BY_LOT_HERDON

## What was wrong before
- The previous individual weighing experience was split from lot workflow and did not provide a practical batch flow per lot.
- In real operation scenarios, user could end up with only one visible individual entry (for example `Animal #1`) when a lot had many heads but no generated individual animal records.
- There was no dedicated lot-level “start -> partial save -> finalize -> summary” flow in `Acompanhamento de Peso`.

## What was implemented
- File changed: `src/pages/AcompanhamentoPesoPage.jsx`
- New practical flow in Portuguese:
  - `Pesagem individual por lote`
  - `Selecionar fazenda`
  - `Selecionar lote`
  - `Data da pesagem`
  - `Gerar animais individuais para este lote`
  - `Salvar progresso`
  - `Finalizar pesagem do lote`
  - `Resumo da pesagem`

### 1) Animals listed/generated by lot
- After selecting lot/date, the screen lists all individual animals linked to that lot.
- If there are no individual animals:
  - A safe action is shown: `Gerar animais individuais para este lote`.
  - Placeholders are generated as `Animal #1...#N` based on lot head count (`qtd`, `qtd_inicial`, etc.).
  - Each generated animal is persisted linked to `lote_id`.
  - Duplicate generation is prevented by checking existing labels in the same lot.

### 2) Partial weighing save
- For each animal, user can type:
  - `peso atual`
  - optional observation
- Rules implemented:
  - Numeric weight required only when value is filled.
  - Empty weight is allowed during progress.
  - Partial save persists only filled valid weights.
  - Returning to same lot/date restores persisted values on screen.
- Duplicate same-animal/same-date weighing is prevented:
  - If a weighing for same animal/date exists, it is updated.
  - Otherwise, a new one is created.

### 3) Final lot weighing summary
- On `Finalizar pesagem do lote`, app saves progress and shows summary with:
  - total de animais do lote
  - total de animais pesados
  - animais sem pesagem
  - peso médio
  - maior peso
  - menor peso
  - variação entre maior e menor peso
  - data da pesagem
  - fazenda
  - lote
- If previous animal weighing exists, it also shows:
  - ganho médio desde a última pesagem
  - evolução do peso médio
  - quantidade de animais com ganho
  - quantidade de animais com perda
- If not enough previous data:
  - `Sem pesagem anterior suficiente para calcular ganho.`

### 4) Cloud persistence behavior
- Uses existing operational persistence helpers (`createOperationalRecord`, `updateOperationalRecord`, `persistCollectionMutation`).
- Cloud available:
  - Saves automatically.
  - Shows `Pesagem salva na nuvem.`
- Cloud failure:
  - Falls back to local/pending mechanism already implemented in persistence layer.
  - Shows `Pesagem salva localmente. Sincronização pendente.`
- No token/JWT/secret logging was added.

### 5) Statistics/charts integration
- Individual weights are persisted as `pesagens` with `tipo: 'animal'`.
- On finalize, a lot-level weighing record (`tipo: 'lote'`) is upserted for selected date with computed average.
- Lot fields are updated (`p_at`, `peso_atual`, `peso_medio_atual`, `ultima_pesagem`).
- Existing lot history/chart (`PesoChart`) now consumes that finalized lot weighing record without breaking existing contracts.
